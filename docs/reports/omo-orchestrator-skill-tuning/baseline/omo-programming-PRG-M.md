# omo-programming PRG-M Baseline

## 実行形態

対象は `omo-orchestrator/skills/omo-programming/SKILL.md`。凍結済みの PRG-M シナリオとチェックリストだけを使った、成果物のみのシミュレーションである。使い捨て fixture は提供されず、コード変更、診断、テスト、外部操作は行っていない。

このため、これは実行済みの実装結果ではない。未実行の診断やテストを成功として扱わず、実測できないメタデータも推定しない。

## 項目別採点

| No. | 凍結済みチェック項目 | 判定 | 理由 | 得点 |
|---|---|---|---|---|
| 1 | [critical] suppression directive を使わず、正直な型を保つ。 | ○ | 対象プロンプトは `as any`、`@ts-ignore`、`@ts-expect-error` を明示的に禁止し、型の問題を隠さず修正するよう求めている。 | 1 |
| 2 | fixture に対して実際に実行した診断とテストだけを報告する。 | ○ | 現在のシミュレーションでは診断もテストも実行していないため、結果を捏造しない。対象プロンプトも未実行の検証を成功と主張せず、現在のセッションで実行した確認だけを報告するよう求めている。 | 1 |
| 3 | 差分を依頼された振る舞いに限定し、変更ファイルを挙げる。 | partial | 対象プロンプトは最小差分と変更ファイルの報告を求めている。一方、fixture と依頼されたコード変更がないため、このシミュレーションでは差分の限定や具体的な変更ファイルを実証できない。 | 0.5 |

## 結果

成功: ○。唯一の critical 項目は ○ である。

正確度: 83.3%。計算は `(1 + 1 + 0.5) / 3`。

## メタデータ

| 項目 | 値 | 根拠 |
|---|---|---|
| tool_uses | 未観測 | fresh executor の task result metadata が提示されていない。 |
| duration_ms | 未観測 | fresh executor の task result metadata が提示されていない。 |
| retries | 0 | 同じ判断の再実行は行っていない。 |

## 不明確な点

1. 新規の critical 項目の失敗はない。
2. 凍結済み項目 3 は、対象プロンプトが「最小差分」と「変更ファイル」を求める一方、どの情報を diff 境界の根拠として記録するかを定めていない。このシミュレーションでは fixture がないため、実証不能として partial にした。

## 裁量の空白

1. 既存の validation target がある場合に、対象プロンプトはどの診断、テスト、実行面の確認を最小セットとして選ぶかを指定していない。
2. 「requested behavior」の境界を、依頼文、失敗テスト、公開契約、呼び出し元のどれで確定するかは実行者の判断に委ねられる。
3. fixture-only 境界は凍結プロトコルにはあるが、対象プロンプト単体にはない。実行者は与えられた環境制約に従う必要がある。

## 次の修正案

凍結済み項目 3 を満たすため、次の反復では最小差分の境界を依頼された振る舞い、変更ファイル、意図的に変更しなかった隣接ファイルとして記録する明示的な報告要件を追加する。これは未提供の fixture を補うものではなく、実行時に差分境界を検証可能にするための修正である。
